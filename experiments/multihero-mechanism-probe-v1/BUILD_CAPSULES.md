# Incremental capsule build and loaded-library preparation

**No real build, loader invocation, native write, shared lease acquisition, or game was performed.** `build-plan-only-01/PLAN.json` is an actual default prepare-only invocation. `CAPSULE_CPU_AUDIT.json` exercises temporary fake trees and mocked compiler/loader calls only. It is not a native compile or recovery certificate. Current threatreleaseA inputs remain untouched.

`build_capsules.py` defaults to writing only a new plan under its required `--out`. The plan records exact candidate SHA, helper SHA, intended source/build paths and future steps; it does not hash the entire live tree, acquire GPU/pool leases, or mutate native input. A future explicitly scheduled `--execute` performs the following under GPU-learner **then** pool exclusive nonblocking leases. Busy acquisition exits nonzero, closing the first lease if the second was busy; it does not wait and later infer permission.

1. Reject still-running native processes using the accepted bin/library. Before touching source, back up accepted Director `.cpp/.h` bytes/modes, three published binary payloads/modes, and a complete source-tree file SHA manifest. Git metadata is excluded. File symlink targets are hashed. Exactly data/Data, data/Maps, data/Mods targeting /root/heroes3-ai-lab/data/vcmi/{Data,Maps,Mods} are classified as fixed runtime assets and recorded without traversing/copying the game assets. The exact reviewed dangling root model link defender-ipnkyfqb-best3.onnx to ../export/defender-ipnkyfqb-best3.onnx is recorded as missing runtime model data, without a target SHA; see SYMLINK_REVIEW_03.md. Other external source-directory or unknown dangling links, and altered targets for any fixed name, are rejected.
2. For each of `original-unhandled`, `close-only`, `transfer-close`, verify candidate SHA against the plan, temporarily write its source/header with current mtime, and capture the exact full build-source manifest. Only the two Director source files may differ from base. Run verbose `ninja -C <build> -v vcmiclient vcmiserver`; exit zero and an observed Director compilation command are required. Rehash source after compilation.
3. Copy three actual binary artifacts and full `bin/config` into a new variant capsule, together with candidate Director and certified server source snapshots, complete base/build manifests, and raw build log. `BUILD_ATTESTATION.json` binds these artifacts, manifests, build command/log/exit and source paths. `libvcmi.so` must differ from accepted; `vcmiclient` may remain byte-identical. This is expressly **incremental from the accepted shared tree**, not an independent full clean build. Unchanged base source files have a complete manifest, not redundant copies of the entire source tree in every capsule.
4. In `finally`, with both leases still held, write accepted Director source/header back using **current mtime**, then run verbose ninja again. This rebuild is mandatory even after a failed probe build: restoring source bytes alone can leave probe object/archive files for later accidental linking. Require complete accepted source-manifest equality and all three rebuilt published binary SHA to match their backups. Capture `ldd` resolution of both accepted executables under accepted `LD_LIBRARY_PATH`, proving the resolved lib path/SHA. This loader-resolution check launches no game and is not claimed to be `/proc` evidence from a native run.
5. If rebuilding/restoring fails or rebuilt bytes differ, keep all failed logs, restore the backed-up published binaries and source payloads, verify what was restored, and report `rebuild_required=true` plus any per-file fallback failures. Do not permit capsule running merely because published bytes were copied back: the build graph still requires investigation/rebuild. Overall driver exit is nonzero for any variant or restoration failure. SIGTERM/INT invoke the same restoration path and terminate only the owned compiler session; catastrophic SIGKILL/power/storage failure cannot promise `finally` and requires manual recovery from `accepted-backup`.

No game runs during the build driver. A capsule is runnable only after the parent directory's `EXECUTION.json` reports all variants complete, exact accepted-source/published-bin restoration, and `rebuild_required=false`. The attestation reader checks that restoration record, the registered attestation SHA, every artifact, manifest/source linkage, independent regular binary copies, and build log. It does not claim native loading before a game occurs.

`run_probe.py --capsule <capsule> --variant <variant> --out <new-run>` defaults to preparing only a native plan. Later explicitly scheduled `--execute` acquires the same GPU→pool NB leases, launches only the capsule binary with its `LD_LIBRARY_PATH`, and explicitly sets server.useProcess=false, matching the actual ServerThreadRunner source. It observes the native client process in that owned session. For each actual `/proc/<pid>/exe` and unique `/proc/<pid>/maps` libvcmi path it verifies resolved capsule location, device/inode identity, file SHA and artifact SHA; deleted/wrong mappings fail. File SHA caching keys include device, inode, size, mtime and ctime. The client must load the attested library, have an observed /proc/<pid>/task/<tid>/comm named runServer, and emit native CVCMIServer startup and Server-gives-turn logs. A separate vcmiserver process is not required and contradicts this explicit thread mode. Missing thread or server-log evidence fails rather than assuming the server ran. All input artifact SHA are rechecked by the offline raw auditor after the game. A changed implementation library or printed loader environment alone is insufficient.

The raw gate still requires genuine meeting/MoveHero/ArrangeStacks/query/EndTurn ACK evidence and conservation. Loaded-library proof adds build identity and does not substitute for those mechanics. A successful controlled stop remains nonterminal with no winner and zero learning. Original-unhandled remains negative evidence. Postboundary raw events are retained.

The temporary fake-tree CPU tests cover normal restoration/current mtime/accepted rebuild, variant build failure, accepted rebuild failure with backed-up binary fallback and `rebuild_required`, unchanged-client/changed-library acceptance, actual mapping parser path/inode/device/SHA rules, deleted/wrong inode rejection, source tampering rejection, and busy-pool release of the previously acquired GPU lease. They never start a compiler, `ldd`, native game, or actual shared lock. Prepared sources remain uncompiled; their first real build can still reveal C++ issues, and no protocol success is promised in advance.

Future commands, only after explicit scheduling:

```text
python build_capsules.py --out <new-build-root>                 # prepare only
python build_capsules.py --out <different-new-build-root> --execute
python run_probe.py --capsule <successful-build-root>/close-only --variant close-only --out <new-run>  # prepare only
python run_probe.py --capsule <successful-build-root>/close-only --variant close-only --out <another-new-run> --execute
```

Use WSL Python and absolute WSL paths. Never reuse a populated output directory or execute while parent experiments are still running. Build/runtime preparation makes no change to the causal threatreleaseA experiment and must remain a separate versioned engineering acceptance.
