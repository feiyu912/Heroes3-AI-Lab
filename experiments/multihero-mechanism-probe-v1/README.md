# Review-only native multihero mechanism probe

Prepared implementation only. **Not compiled, installed, or run in VCMI.** No pool/GPU was acquired. `CPU_PREPARATION_AUDIT.json` is explicitly a synthetic gate test, not proof that hero meeting, transfer, or the new C++ code works. All code/maps/diffs here are independent of frozen training source, model, native binaries, and the threatreleaseA experiment.

The current proposal is **`candidates-02/`**. It contains three diagnostic DirectorAI replacements, each with `.cpp`, `.h`, and full source diff from the actual WSL Director snapshot audited in `strategic-fullgame-capability-audit`. `candidates-01` is an earlier uncompiled draft retained separately; do not install it. Registration remains `DirectorAI` only inside a future separate native installation, so current native paths must never be overwritten. No installer or compiler invocation is provided or performed.

## Three variants

| Variant | Behavior after the real hero-exchange callback | Intended result |
|---|---|---|
| original-unhandled | Log callback and army state, then do nothing, reproducing the original inherited callback's lack of reply/transfer. | Preserve actual unanswered-query/rejection/timeout evidence. Never declare successful exchange or winner. |
| close-only | Mark actual query pending, send `selectionMade(0,real_qid)`, await successful reply ACK and QueryResolved, then EndTurn ACK. | Establish query liveness only, without changing army allocation. |
| transfer-close | Keep real query open, native merge/swap one legal courier stack into receiver, await that exact ArrangeStacks request's successful ACK, then send QueryReply and await close ACK, QueryResolved and EndTurn ACK. | Establish conservative transfer plus query liveness, not courier strategy or full-game ability. |

All variants disable economy, saving requests, and external candidate policy functions. Init refuses `LAB_ADV_AGENT_DIR` and requires its own probe log. They directly select the owned nongarrison hero with smallest object ID and target the other real owned hero's distinct visitable tile through native pathfinder. The next path node must be available this turn and different from current location. `MoveHero` still uses the actual native object-coordinate conversion. No candidate is added to schema3; no broker request/action file or PPO sample is produced. The generated sources omit `chooseExternalCandidate` and `traceDecision` entirely.

The fixture has two red heroes, a remote blue hero, and both towns. Objects besides heroes/towns are removed. Courier starts with 10 Pikemen + 3 Archers, receiver with 5 Pikemen. The prepared map object coordinates are (10,12,0) and (12,12,0), not claimed to be visitable coordinates; native computes those. `fixture-01.vmap` is derived deterministically from the real training map with the terrain/templates/normal native rules retained. Its SHA256 is `ab20ed070f644a545947e1c55ce39af5326b815fbbfab7cad4fe9e39f82b6d39`. It has **not** been native-loaded; a path/load failure is a failed engineering case to diagnose, not an excuse to inject a fake candidate or use a same-location move.

Transfer requires two courier stacks and at least one receiver stack. It sends only one whole-stack merge/swap into a matching/free slot, so the other donor stack remains. Runtime snapshots independently verify both heroes retain at least one unit, total counts per creature are conserved, donor loss equals recipient gain, coordinates/resources are unchanged during exchange, and close-only does not change armies. This fixture does not test arbitrary splitting, seven occupied slots, nonremovable map garrisons, or all possible stack arrangements.

## Prepared runner and raw evidence gate

`run_probe.py` now accepts future `--capsule`, `--variant`, and a **new** `--out`. It requires a successful incremental build attestation and accepted-build restoration record, candidate source snapshots, independent regular binary copies, and the certified three-source server barrier manifest. A dynamically linked client may correctly remain byte-identical; the implementation-bearing library, source manifests and actual loaded process mappings establish identity. It does not build/install anything. By default it only prepares plan/configuration files. **Only a later explicit `--execute` launches a game.** Do not invoke that mode until the parent schedules the separate capsule after threatreleaseA. See `BUILD_CAPSULES.md` for the reviewed build/restore preparation.

The runner acquires the GPU learner lease then shared pool lease, both nonblocking, for its one owned native process group and CPU-only AI. A busy lease exits without launching. It stores source/bin/map/config/script SHA, complete raw client log, full native state trace, independent `multihero-native-mechanism-probe-v1` query/request events, and actual client/server `/proc` executable and libvcmi mapping paths, inode/device identity and artifact SHA. Server mode is explicitly useProcess=false. The client library mapping, actual runServer task/comm, and native CVCMIServer startup/turn logs must all be observed; no independent vcmiserver process is required. It stops its own process group after a proven EndTurn ACK; successful results are `game_completed=false`, `winner=null`, `optimizer_steps=0`, `training_samples=0`. Negative original-unhandled may stop on native query rejection; otherwise the bounded timeout remains `timed_out=true` and no winner is assigned. It terminates only the newly created native process group, never unrelated training processes.

`audit_run.py --run <directory>` is read-only. For positive variants it requires all real move request IDs to have native successful ACKs and move-result replies, raw step logs with distinct source/destination targeting the receiver's real tile, native object-visit log, exactly one exchange callback, matching query/request identities, ACK-before-close ordering, query resolution, successful EndTurn ACK and empty pending queues at the completion marker. It rejects native failures/rejections and terminal victory/defeat. It checks troop conservation, residual units, unchanged close-only armies, frozen hashes, and absence of policy request/action artifacts. Postboundary notifications remain in raw logs and the report; extra move/transfer/reply requests after completion are rejected.

The source event stream supports the audit; it is not a substitute for raw native movement/visit/ACK/state evidence. The old unhandled variant cannot pass the positive engineering gate merely because its callback fired. This bundle contains **no real run directory** and makes no native success claim.
