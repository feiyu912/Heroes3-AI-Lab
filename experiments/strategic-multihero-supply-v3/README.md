# Scripted supply cargo v3

This is an isolated, unbuilt candidate derived from frozen supply-v2. V1/v2 sources and the real partial native run are preserved. No shared build, native game, GPU work or resource lock was used for this candidate. Existing native reports describe v2, not a successful v3 delivery.

The v2 raw run `scripted-supply-native-01` exposed a concrete cargo failure: native request8 transferred town3's 10 Pikemen to courier2 slot1, but request53 delivered the courier's original slot0 3 Archers to main0. The original reserve was chosen by slot order. The main retained only 5 Pikemen; the picked-up 10 Pikemen remained with the courier. Both transfers really changed armies; this is a controller semantic defect, not a request-execution diagnosis. RAW_V2_DIAGNOSIS.json records the read-only trace evidence; full server/ACK evidence is independently reviewed elsewhere.

V3's behavior epoch is `scripted-supply-cargo-v3`; its trace schema is `scripted-supply-events-v3`. The existing explicit switch `LAB_ADV_MODE=scripted_supply_v1` and internal supply_v1 namespace remain for source compatibility. Old schema4 policy/model/optimizer/encoder inputs are unchanged, and no script operation is a PPO transition. Use an absolute LAB_ADV_SUPPLY_TRACE path. V3 cannot be treated as an old-epoch checkpoint resume.

## Cargo and reserve rules

At controller start, record the courier's actual seven-slot army as initialReserve and derive reserve counts by creature. Only after a real positive, exact native pickup ACK and verified complete donor/recipient slot deltas are picked, cargo_remaining and cargo_slots increased. Prepared/sent pickup requests do not create cargo credit. Cargo and job state persist across own turns.

A delivery may select a whole slot only when that entire actual slot equals its acknowledged pickup contribution. The donor must retain its original reserve creature/count in each original reserve slot and at least one army stack. The controller tracks contribution counts by slot and creature; it does not track individual soldier identities. Native reordering, war losses or untracked changes that invalidate those obligations fail closed. This deliberately conservative first implementation does not claim that the engine can never reorder stacks.

Consequently the real regression's slot0 Archers are not cargo, and slot1's 10 picked-up Pikemen go to main's compatible Pikeman slot. Same-creature reserve3 plus pickup10 merged to one stack13 cannot be delivered by a whole-stack operation while preserving reserve3: no split is issued. Initial duplicate same-creature reserve slots cannot be substituted as cargo merely because one slot is smaller than the outstanding creature count. Such meetings close explicitly incomplete. Matching or empty recipient slots are allowed; an incompatible full receiver is never swapped. Partial deliveries preserve remaining contribution ledgers and report incomplete rather than success.

Job status codes are Empty=0, Carrying=1, Delivered=2, Incomplete=3. A new job ID starts on the first real pickup ACK after Empty/Delivered. Additional pickups for an outstanding job add to the same job. `successful_jobs` increments only on the real intended exchange-close ACK when picked is nonempty, cargo_remaining is empty, picked equals delivered, and the initial reserve is still present. Transfer ACK alone, sent close, generic QueryResolved, accidental meeting and partial delivery never satisfy completion. Success refers to all acknowledged pickups for this job; it is not a claim that every available town creature was recruited or transported. A requested external cargo objective still needs independent comparison against picked/delivered totals.

## Preserved scheduling/request barriers

Exactly two real owned heroes are required; min/max actual ID assign main/courier and lowest valid own town is home. No role or death replacement is fabricated. Round robin excludes garrisoned/naval/exhausted/blocked actors. The ordinary actor threshold is 48 requests; a live exchange can drain up to six additional whole-slot cargo transfers. Only native player EndTurn is sent, after actors yield. The scripted main frontier patrol still has no long-horizon target commitment and may outrun the courier; no strategic improvement is claimed.

The single scripted adventure pending command survives until its exact positive native ACK. Native BattleAI/interface requests remain separate genuine client-ledger activity. Director-only pre-dispatch binding and actual payload guards are inherited from terminal-drain-v3. Early NewTurn queues behind the prior EndTurn ACK. Real heroExchangeStarted opens a meeting; transfer waits for the originating move ACK and can drain the exchange while ONGOING_MOVEMENT remains blocked. Actual QueryReply ACK closes it; this native query has no QueryResolved notification. Accidental contacts only close and restore the prior phase, without a job success/cycle claim.

## Native audit observations

Each event is constructed once and mirrored verbatim as `DirectorSupplyEvent <json>` in client.log and as the same JSON plus newline in the trace file. It exposes both real owned heroes and own towns with ID, position, visitor and seven actual creature/count slots. `actual_request` on native_sent/prompt_native_sent records actual request_id/player/pack_type and complete MoveHero hero/path/layer/transit, ArrangeStacks source/target/slots/what/val, QueryReply query/reply or player EndTurn scope.

Each event adds `job` with id, status, successful_jobs, incomplete_attempts, success, reason, initial_reserve_slots, cargo_slots, reserve, picked, cargo_remaining and delivered. Slots are seven creature/count pairs; count ledgers are sorted creature/count pairs. `real_ack` runs inside the actual PackageApplied callback before the controller update: world armies are already updated, but ledgers/pending are still the previous values. `control_ack_applied` immediately follows successful conservation checking and ledger/pending updates, before the next script request; on close it exposes the completed/incomplete outcome. These callback events may precede CClient's later unified NativeRequestAck print. An auditor must bind the actual request and callback, not impose the opposite print order.

## Recovery restriction

Native restore remains explicitly rejected with LAB_ADV_SUPPLY_RESTORE. New C++ members are not automatically serialized by the engine. The atomic sidecar metadata utility has a new cargo-v3 epoch and requires complete reserve/cargo/job fields and pickup=delivered+remaining consistency. It still has no native SaveGame/sidecar/fresh-process C++ hydration integration. Its synthetic fresh-process tests are metadata checks, not native restoration proof.
