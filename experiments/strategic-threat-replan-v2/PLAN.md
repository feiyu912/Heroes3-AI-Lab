# Bounded visible-threat replanning, v2

Pre-execution plan. Preserve accepted V8, historical typed/ACK capsules and all frozen battle files. No optimizer or new expert labels. Same frozen539850b6… CPU argmax policy in both arms of one newly compiled native capsule; runtime mode explicitly off/once. Candidate count changes observations, so outcome effects are availability/observation effects, not learning gain.

Once mode can interrupt an existing, still admissible committed goal at most once per hero per own turn, only when the already generated legal move pool has alternatives and a currently visible enemy hero has approximate army >=1.5 times own army, on the same map level and within Chebyshev12. This threshold is a fixed research parameter, not a verified interception distance or safety guarantee. The triggering decision keeps the original full native legal candidate list; after choosing, the new goal is committed normally. The budget is consumed even if the model keeps its old goal. No repeated per-step release, fabricated hold/move/ACK, unsafe attack bypass or hidden enemy data.

The first implementation adds no new escape tile, empty-town goal, safety reward or tactical behavior. Genuine EndTurn remains player-wide and attackable. This phase tests bounded replanning availability before separately testing defensive candidate construction. All scheduler/query/movement/battle/terminal gates and native Lua damage assets are retained. No callback may invoke a new action early.

Required evidence: actual pure C++ predicate thresholds/invalid inputs and budget; locked compilation plus exact accepted source/bin restoration; off-mode true native regression and whole-game apply/ACK/terminal audit; once-mode release log bound to the published request/current visible threat/previous selected goal, one per(hero,own_turn), only native-generated candidates; same binary/model comparison with all pairs retained. Check hidden opponent movement prefixes as well as initial visible requests; neither seed equality nor initial request equality proves identical worlds.

Training-map diagnostic schedule, not final test or unseen strength certification: train01-mines/train02-development × EmptyAI/Nullkiller2 × red/blue, seeds2026110900..07 in that order;8 pairs/16 games, mode off then once. Primary outcome normal native win/loss. Invalid game stops the batch, is unscored and never trains. Secondary: actual releases, multiple available moves, whether the chosen destination changes, days and request count. Before all pairs run, two off/once engineering qualification games may use the first Empty cell; repeats are excluded from scored diagnostic endpoints. No outcome-based seed selection, no superiority claim from a small batch, no default promotion without review.
