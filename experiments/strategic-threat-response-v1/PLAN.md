# Threat response v1: proposed protocol, not authorized native implementation

Status: source review, standard-library CPU contract and archived visible-state replay only. No native/compiler/model/collector changes, games, pool use, GPU use or optimizer updates in this directory. Implementation and native experiments await root's decision after the current v3 PPO and paired-development baseline. Existing immutable evidence stays untouched.

## Problem and two distinct phases

The fixed acceptance06 development batch had seven NK losses: five original heroes were attacked by an enemy and two died initiating a town siege. Four pursuit deaths had a visible >=1.5× enemy within grid8 beforehand; the fifth had one at grid9. Four pursuit victims' final requests offered a single committed candidate. Some towns had substantial unclaimed reinforcements; others were empty after real replenishment, so universal return-to-town is not justified. These are diagnostic observations, not intervention outcomes. Source: ../strategic-server-barrier-readonly-audit/NK06_FINDINGS.md and its per-file SHA/line evidence.

**Phase A is the smallest native prototype: release-only, schema3, all actions still real MoveHero.** Modify only the isolated Director variant's commit-collapse branch. Before `candidates.assign(1, committed)`, if a currently visible enemy hero has approximate army >=1.5× own and same-level Chebyshev distance<=12, clear this hero's commit and retain the already generated complete legal native candidates. In pressure mode skip collapse on each scheduling call. No threat means exactly the original commit behavior. The radius12 is an explicit new candidate parameter, chosen conservatively to include the grid9 observation; it is not a measured interception radius. It must be frozen before future games. Far-away enemies, other levels and unavailable information do not trigger. Recompute only inside the existing native scheduling barriers, not from enemy-motion callbacks.

Phase A adds no hold, no escape tile, no empty-town reinforcement candidate and no unknown map destination. The existing native pathfinder continues to determine valid current next steps and true path costs. Retreat means selecting one of these legal movement candidates. An optional separate CPU policy may rank existing next steps for larger visible-enemy coordinate clearance with cost-aware own-garrison support; it never predicts reachability or victory. A single archived candidate stays single in CPU replay: removed candidates cannot be reconstructed from the request. Only a future native variant can expose them.

**Phase B is optional schema4 with typed end_turn.** It adds a genuine player-wide stop using EndTurn, initially only in states with exactly one own hero. It is not hero-specific hold and may sacrifice economy/other remaining actions; economics is drained before decision generation. Full multi-hero hold requires a separately specified scheduler and audit and is outside v1. A stopped hero remains attackable; end_turn is not advertised as defensive safety. No same-tile MoveHero, invented path, simulated ACK or synthesized successful transition stands in for this action. Phase B must not be slipped into schema3 or run with the old collector/model/auditor.

## Phase B wire, model, rollout and recovery migration

Request schema `strategy-candidates-v4` must carry current v3 visible observations plus explicit own_hero_count, commit status and typed candidates. A move is `{op:move,kind:0..5,position,next,path_cost,heuristic_score}`; player stop is `{op:end_turn,scope:player}` with no position/next/path fields. Action response remains one in-range candidate index, so native dispatch—not the broker—decides which genuine pack is issued. Candidate order and semantic fields are hash-bound to decision record; current native generation still authorizes every move. EndTurn appears at most once and only under the defined single-hero/no-blocker conditions. No implicit migration from missing v3/v4 fields.

Use a new versioned encoder: preserve v3 feature transforms for move rows, append explicit action-type bits and an own-hero-count state feature. EndTurn has zero move-feature payload with op bits distinguishing it; this is an explicit new representation, never a fabricated v3 position. Its scoring has an explicit separate stop head/default prior rather than borrowing the move heuristic prior. Import v3 actor/critic input columns by named feature manifest into the new networks; initialize new columns/stop head deterministically and save a new format including source checkpoint SHA, op schema, initial stop bias and native variant SHA. Demonstrate exact old move logits in a moves-only fixture (including masked prior handling). Value predictions change if pooled candidates include stop, so preservation applies only to moves-only fixtures; no claim of matching the new full policy distribution. Warmup stop behavior is an engineering design choice, not learned skill.

Typed native trace must bind `(decision_id,native_request_id,player,op,hero identity,own_turn)` in before/action-sent/confirmed records. Count decisions = confirmed MoveHero + confirmed selected EndTurn, not all automatic end-turn calls. Preserve zero-displacement interactions as genuine MoveHero. Require real server receipt and application plus exact ACK for the stop in the initial pilot; natural terminal before a stop ACK remains invalid unless a separately versioned native proof certifies the actual EndTurn application. Never infer action execution from winner, BattleEnded, a local skip flag or response-file existence. A client may receive next turn before prior EndTurn ACK; maintain pending typed action by requestID independent of reset per-turn flags, never let a delayed ACK clear a new turn's state.

Training may retain terminal ±1 episode rewards and complete-episode GAE with one transition per verified typed decision; no positive reward for holding, apparent survival or distance. If discounting is per decision, new stop actions alter the decision horizon; record gamma/time convention and use matched phase-B policies, not raw v3 return comparisons. Timeout is invalid—not loss, terminal or an update row. Save/load native state only at no-active-battle turn boundaries. Checkpoint stores schema4/encoder/typed rollout version and any outstanding episode status; reject v3 optimizer/rollout resume under v4. No pending native action may be silently discarded to manufacture a boundary.

## Separate siege and tactical work

The two active siege losses had visible army scalars weaker than own, yet lost. Keep siege diagnosis separate from a threat release rule. Native wall/tower/garrison/hero/spell effects need visible-information evaluation and paired battle tests; army ratio alone is not an attack certificate. Do not silently treat unknown defender details as zero. No combat surrender/retreat callback changes in this strategic prototype: Director currently returns nullopt in makeSurrenderRetreatDecision (cpp807–810), a separate tactical interface with different legality and army/hero consequences.
