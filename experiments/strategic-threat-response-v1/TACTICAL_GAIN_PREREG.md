# Optional permanent-gain tactical curriculum: proposal only

No new games, teacher demonstrations, expert labels or training data are produced by this file. Withdrawn quality tags remain withdrawn. Old favorable examples or subsets cannot be used as evidence for this proposed course. This is an independent prospective protocol requiring native event and whole-course benefit validation.

Start with a deliberately narrow spell-free survival course so temporary healing, mana valuation and hidden enemy spells cannot masquerade as lasting benefit. All units/actions must already be supported by the native battle interface. Fix8 roster/layout scenarios before outcomes are collected: four mixed melee/ranged groups protecting a shooter, two melee-screen layouts and two retreat-distance layouts. Specify exact faction/creature/count/terrain/obstacle/hero skills and side swaps in a frozen scenario manifest before running; this document does not invent that missing manifest. Use no hero spells, no permanent-stat artifacts and identical hero modifiers in both arms. Fairness requires the baseline and teacher have exactly the same allowed spell-free action set.

For each scenario use four fresh native seeds on both roles, giving64 paired battles (128native executions) in the development course. Teacher and baseline receive identical current player-visible snapshots and native legal actions. Candidate teacher is a fixed depth2 approximate exchange/range evaluator over current visible state; it may calculate expected damage intervals but must never read or clone the engine's unrevealed next RNG draw. Do not call a seeded approximate roll the real game's next random outcome. Native paired common seeds are controlled by the evaluator, not supplied as a feature to the teacher. Fixed action tie-breaking and an operation budget are part of the manifest. Baseline is the original native BattleAI; do not silently replace or handicap its legal action set. Spell-free fixtures must naturally expose no legal hero spell actions in the engine, rather than filtering baseline actions after generation.

Primary endpoint is the paired difference in **real permanent surviving friendly army value after full native battle cleanup**, using a frozen public unit-value table and actual final creature counts. Both combatants' victory/loss, hero survival, permanent losses and battle turn count are reported. A same-battle temporary revival or a locally favorable damage event is not permanent gain. Native final stack/removal/resurrection-cleanup events and postbattle strategic army snapshots must agree. If final strategic state cannot be recovered, the example is unverified and excluded from certification; an exclusion invalidates the registered course and requires an explicit new version, not a shorter favorable subset.

Certification requires: all native action/event audits valid; no teacher loss where its paired baseline wins; no increased permanent friendly casualty value in any registered pair; and the aggregate mean permanent survivor gain has a strictly positive one-sided95% paired confidence lower bound (whole scenario clustered, reporting all pairs). Because such strict conditions may fail, failure is a normal result and yields BC0. Victory-only gains with increased casualty costs cannot be called an approved permanent-gain course under this protocol. No mana or spell budget tradeoff is inferred because the course excludes spells.

After passing development, freeze the complete teacher/scenario/metric code and test the same course on two further untouched seed values for every scenario/role (32pairs,64executions), with no tuning after seeing results. Apply the same exact native/permanent-gain gates and report all pairs. These are independent course holdouts, not strategic full-game test maps. Only a passing full course may produce a versioned expert dataset; each trace still needs exact action consumption and event proof. Training subsequently requires a separately frozen BC-vs-control evaluation; teacher improvement does not prove the learner improved.

No seed values or concrete roster manifest are assigned here to avoid colliding with ongoing registered experiments. They must be finalized and hashed before the first course run. Until then this is a prospective design, not an executable experiment or expert certification.
