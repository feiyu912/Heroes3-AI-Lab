# Fixed eight NK games: strategic failure evidence

The seven losses contain **five original main heroes killed by an enemy-initiated attack and two killed while actively attacking an enemy town**. This comes from native battle text immediately before the original hero's RemoveObject, cross-checked against whether the last native battle START follows own turn_end or own before_move. One win retains its hero; the old audit's terminal_betrayal label is kept distinct from combat death. This is not evidence that every visible strong enemy is reachable, nor that every retreat would win.

`NK06_FAILURE_ANALYSIS.json` contains request file SHA, native log/trace SHA and exact lines for every row. Only legally visible v3 request information is used for threat and supply calculations. “Strong” here is a diagnostic enemy approximate army scalar >=1.5× own; “near” means same-level Chebyshev grid distance<=8. These thresholds are descriptive, not certified combat or interception models. Original hero requests stop at its first native disappearance: a later recruited hero can reuse the numeric ID, so later requests must not be mixed into its first life. An initial diagnostic JSON that did not apply this cutoff is retained with INITIAL_DIAGNOSTIC in the name; use the corrected file.

Supply is a mixed limitation, not a universal explanation. In the final seven-day windows, positive-garrison legal kind4 opportunities existed in44/31/45/38/66/17/0/18 requests respectively (many are successive steps committed to the same supply destination, not independent choices). Two pursued heroes had empty towns because they had already collected supplies: map01red61 most recent real supply approach day39r424 cost0.0871 with1624 value adjacent, and map01blue62 day70r691 cost0.0949 with6055 adjacent. They still died to roughly2.0×/1.84× visible enemies. Returning to an empty town cannot solve those deaths.

Other cases have real unused reserves. The most supported next mechanism is **legal threat-responsive target release and a genuine safe-stop/retreat option**, tested separately after currently scheduled training finishes. Visible stronger enemies precede all five pursuit deaths; four enter the near diagnostic radius, while the fifth is visible at grid9 just before death. Four of these five final original requests have only one committed candidate. A learner cannot change a one-action request, and the current legacy projection ignores the v3 threat/supply extras. Add no fake paths or hidden future movement: the native layer must explicitly expose legal alternatives/release, retain real path costs and request ACK barriers, and evaluate a fixed paired development protocol. Where a multi-action request already exists (map02blue61), representation, selection and combat attrition still need attention.

Separately, both active siege losses occur while the approximate visible enemy army scalar looks weaker than own (3543vs14350,97620vs123027). Therefore that scalar is not a certified siege outcome model. Siege walls/towers, garrison composition, heroes and spells need proper native-mechanism validation before using the ratio as an attack permission. Do not simply increase a ratio threshold and call it verified counterplay.

These observations support mechanism and representation changes, not extra random PPO rounds alone. There is no same-seed old-economy paired baseline in this batch, no held-out test evaluation and no new gradient update. No expert curriculum or BC labels are certified.
