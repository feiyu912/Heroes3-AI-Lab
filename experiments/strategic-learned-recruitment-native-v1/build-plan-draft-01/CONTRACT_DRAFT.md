# Schema6 learned recruitment draft — NOT executable/qualified

Native candidate only, no policy/runner/build or actual game qualification. Parent is learned-economy-native-v2, actual compiled capsule02. The new mode has an unconditional source-level `recruitment_draft_execution_disabled` failclosed gate in init; this is a reviewable implementation draft, not runnable eligibility. Removing that gate requires another reviewed source epoch. All old schema4/5 source branches and loaders remain strict; a schema6 observation is not accepted as schema5.

Mode `LAB_ADV_LEARNED_ECONOMY=build_recruit_v1`. Request schema `strategy-candidates-v6`, economy_epoch `learned-economy-build-recruit-v1`. Request exact top-level keys are the schema5 keys plus catalog binding: `schema,request_id,player,own_turn,own_hero_count,day,hero,from,gold,wood,ore,own_army_value,movement,visible_threats,economy_epoch,economy_window_open,resources,creature_catalog_sha256,own_towns,candidates`. This pilot honestly requires own_hero_count=1. Hero/from continue to identify a real owned hero, not a fake town actor. A zero-hero state may only use the retained native tavern/gold rescue path; if unavailable it auto-Ends with the existing explicit `no_owned_hero` reason. It cannot yet choose a town-only build/recruit policy. Multihero actor scheduling remains an unimplemented full-goal requirement.

Economic choices remain available throughout ownturn, including after a real Move. New `LabLearnedRecruit::select` keeps the window open for build/recruit/move, closes on EndTurn (including automatic End); next ownturn begins open. This differs deliberately from old schema5, whose original window closes unchanged. All actual strategy/movement/economy/battle/query pending guards remain mandatory; no concurrent spending. There is no arbitrary economic action cap. Every recruit ACK must prove exact inventory decrease and destination army/resource delta; built_today/canBuild limits construction; stock/resources are finite, and movement keeps the existing128 limit. Timeout or no progress is invalid, never relabelled as a loss.

Scope boundary: the inherited `issueMove` guard checks movement-cap128 before candidate enumeration, so reaching that cap can auto-End before another economic choice; no-hero policy scheduling is also unsupported as above. “Throughout ownturn” means movement itself no longer closes the window, not removal of those existing controller bounds.

Schema5 move/build/end candidate exact keys remain unchanged. New recruit candidate exact keys:

```
op,actor,town_id,destination_army_id,destination_role,creature_id,amount,
level,destination_slot,quantity_bucket,available,affordable,cost
```

`op="recruit"`, `actor="player_town"`; destination is the actual current `town->getUpperArmy()` object ID, never substituted with a same-town visitor. `destination_role="town"` if that ID is town ID, otherwise `"garrison_hero"`. Direct visiting-hero destination choice is out of this minimal scope. `destination_slot` is native getSlotFor's current destination army slot0..6, a legality observation/recheck, not an invented RecruitCreatures wire field. `level` is the native stock-array index, not destination slot or creature tier inference. `creature_id` is a real nonnegative native ID from that level's offered creature list; no ordinal model meaning or assumed0..N core range is implied. War machines/artifacts and external dwellings are excluded.

`available` is the shared native stock at that level (all offered base/upgraded IDs draw from it). `affordable` is pure native `CCreature::maxAmount(currentResources)`, not min(stock,resources). Let L=min(available,affordable); candidate quantities are unique positive {1,max(1,floor(L/2)),L}. Exact native tuple `(town,destination,level,creature,amount)` is deduplicated; `quantity_bucket` is `one` for1, otherwise `affordable_all` if equal toL, otherwise `half`. Every `cost` is the TOTAL actual native `getFullRecruitCost()*amount`, seven fields `wood,mercury,ore,sulfur,crystal,gems,gold`, and is rechecked with native canAfford. No Python economy approximation creates legal actions.

Each schema5 `own_towns` entry additionally has `recruit_state`, with exact keys `town_id,owner,built_today,resources,upper_army_id,upper_army,visitor,recruit_stock`. `upper_army` is seven slots, each null or `{slot,creature_id,count}`. `visitor` is null or `{hero_id,army_id,owner,army}`, where hero_id==army_id is the actual CGHero object ID, and army is the same seven-slot format. `recruit_stock` is a full list `{level,available,creature_ids}`; creature_ids preserves the actual native offer list. `resources` is the same seven-resource object. No hidden enemy data is read. Creature categoricals in policy require a separately source-pinned vocabulary/UNK; this draft does not assume numerical closeness of IDs.

Runtime catalog is emitted once at new-mode init as `agent/creature-catalog.json`, exact raw keys `{schema,entries}`, schema `strategy-runtime-creature-catalog-v1`; entries are ID-sorted exact `{creature_id,canonical_key}` with nonnegative unique IDs and unique nonempty canonical keys. They come from actual nonnull `LIBRARY->creh->objects`, with real `CCreature::getIndex()` and `getJsonKey()` (`modScope+':'+identifier`, source verified), including public registered special/mod species. No fake fixed core0..N range. Complete bytes include final newline; `creature_catalog_sha256` is SHA256 of those exact raw bytes and every schema6 request carries it. `DirectorCreatureCatalog sha256=... json=...` mirrors the exact JSON without newline. Reusing an existing differing file fails closed. Init can export this catalog then stop at the unconditional draft action gate; this is not a game/action qualification.

The native process does not pretend an ENV capsule name proves its loaded binary. Actual fixture qualification must externally bind this raw catalog SHA/log mirror to actual loaded library/bin SHA, capsule/build-source manifest SHA, exact candidate source closure and qualification proof. That external binding is a separate audit artifact, not an extra unverified self-assertion field in the raw catalog. Policy may load strict raw path+expectedSHA for a draft, but actual training requires the qualified binding and a nonempty registered vocabulary. Unknown future mod creatures may use UNK; training with all species UNK is not qualified. Raw runtime catalog capture is still unexecuted here.
