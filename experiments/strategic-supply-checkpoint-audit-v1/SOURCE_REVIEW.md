# Native supply checkpoint source review

Read-only review of the actual `/root/heroes3-ai-lab/src/vcmi-adv` tree; no native build, game or GPU action. Frozen cargo-v3 and older auditors are unchanged.

`lib/callback/CCallback.cpp:313` sends SaveLocalState with own player/data; `:322` sends SaveGame. `server/NetPacksServer.cpp:436` validates the connection player then writes the JSON to that server player's playerLocalSettings. `lib/CPlayerState.h:71` exposes that JSON and `:126` serializes its contents. `client/CPlayerInterface.cpp:1480` already reads the loaded own PlayerState and explicitly deserializes local UI state. Thus embedding a namespaced Director controller and manually hydrating it is supported by real source. SaveLocalState alone does not automatically hydrate new Director members; the previous overly broad conclusion that localSettings cannot load is withdrawn.

SaveLocalState does not sendAndApply an update back to the current client. Its ACK confirms the server visitor, not necessarily a changed cached client PlayerState. The fresh loaded game must expose the saved server payload and then visibly hydrate the real C++ fields. Preserve other localSettings keys when adding the supply namespace.

`server/NetPacksServer.cpp:32` calls CGameHandler::save and unconditionally reports visitor success. `server/CGameHandler.cpp:1854` creates the vsgm1 resource, writes game and server state, but catches exceptions internally at1890 and logs Failed to save game without rethrowing. Therefore positive SaveGame ACK and Message successfully applied are insufficient. Require the unique intended filename, Game has been successfully saved, a newly produced nonempty VCMI file with stable SHA, and actual fresh native load of exactly that file. `lib/serializer/CSaveFile.cpp:15` writes VCMI magic; `:26` writes the binary with stream exceptions. External metadata must bind that actual binary SHA and compiled source epoch.

`client/Client.cpp:115` loads transferred state and initializes new environments/interfaces. `server/processors/TurnOrderProcessor.cpp:394` handles loading by replaying doStartPlayerTurn for serialized actingPlayers. At280..320, wasAlreadyActing skips deferred onPlayerTurnStarted effects but still emits PlayerStartsTurn. `client/NetPacksClient.cpp:1002` calls yourTurn. Consequently the first loaded yourTurn resumes the current saved own turn: no role re-selection, increment, budget clear, job reset, or native EndTurn. Later genuine turns use the ordinary gate.

In the actual compiled cargo-v3 candidate, visitPackageApplied calls the AI requestRealized callback before logging unified NativeRequestAck and removing the owned registry entry. A callback handling that exact successful PackageApplied has actually received the ACK even though its unified log appears later. Waiting inside that callback for the same log/registry removal deadlocks. Complete raw audit still requires those later actual log entries once the callback returns.

The minimum test checkpoint is own turn2 after at least one completed move, with acknowledged cargo in transit, nonzero spent and nonempty visited/goals. Require no pending adventure/prompt, movement, battle, exchange query, queued own turn or logically unacknowledged owned request. Persist all roles, phase/cursor/budget/blocked/goals/visited and complete reserve/cargo/job state. Invalidate only path caches after hydrate. Transient request IDs may restart; operation payloads, selected actor, budgets, world observations and complete control must agree.

A short nonblocking chain is preferable: clean boundary -> actual SaveLocalState ACK -> actual SaveGame/file -> record the exact snapshot -> return and continue baseline. The external runner can atomically construct a save/source/controller/world bundle after real ACK/file verification, while baseline continues or after its bounded completion. Fresh testSave loads the native embedded payload and matches it to the bundle before acting. No long native callback wait or unsafe background-thread controller mutation is needed. If a hold/release design is used, its resume must be scheduled through a proven safe client mechanism and it must never wait for its own ACK callback to return.

Independent acceptance needs completed native transactions after the checkpoint in both same-process and fresh-process arms, over subsequent own-turn boundaries. Compare the entire selected continuation with EOF handling, excluding only transport IDs/line timestamps explicitly. Equal public own-world projections do not imply complete hidden-world determinism. An environment flag, checksum-only metadata roundtrip, day1 empty checkpoint, or a native file loaded without actual C++ state hydration is insufficient.
