# Supply v4 pre-build review (in progress)

Read-only candidate review, not native qualification. The v3 final auditors and raw are untouched.

The SaveLocalState -> SaveGame callback chain checks the actual dynamic pack, allocated ID, own player and concrete pack type. The local settings payload namespace and SaveGame filename/notify/autosave parameters are validated before transport. recoveryOwned tracks logically unanswered owned requests and removes the current request only after its real PackageApplied arrives. It correctly allows the next metadata request to be sent inside that callback, before the outer unified ACK log/registry removal. There is no external wait or background mutation.

The codec contains roles, own-turn, cursor, cycles, phase and prior exchange phase, job status/counters/reason, initial reserve and cargo slots, all species ledgers, spent, blocked, goals, visited, sorted actual roster/towns and economy projection. It excludes live transactions and rejects noncanonical/trailing data. The native embedded payload is read on newly initialized Director state and manually assigned to actual supply/visited members. The first loaded yourTurn uses recoveryResumeTurn, retaining the saved own-turn/budget/job and invalidating only path caches. This is actual member hydration code, not a flag-only claim.

The lifecycle gate resolves the engine's actual loaded save resource and checks its binary SHA against the bundle, independently of any arbitrary path carried in the bundle. Candidate identity is a SHA token over normalized source inputs with the token placeholder, avoiding a circular self-hash. The final native audit must independently reconstruct that token and bind all thirteen candidate files to the built capsule snapshot and artifact attestation.

Reported blocking issue: the draft Client lifecycle gate applied supply-mode/bundle requirements to every loaded DirectorAI, breaking old schema4 typed-policy saves without a supply namespace. It must gate explicit supply/bundle loading while recoveryInit still refuses a native supply payload without the correct mode/bundle. Read of the optional localSettings namespace must use a const JsonNode alias; unique_ptr dereference otherwise selects the mutating JsonNode operator[] and inserts a null namespace into old typed client state. These fixes were sent to the implementation agent/root; final source recheck remains required.

Other pre-freeze suggestions: reject negative saved visited/goal coordinates and invalid reserve/cargo slot counts; expose actual transient checkpoint boundary flags explicitly; require thirteen files and the exact manifest recovery epoch in runner preflight; accept only checkpoint-turn2, which the native path implements. Relocate the copied bundle save_file field to the actual fresh-copy path and freeze both original/local bundle, so native recovery does not depend on the old reference file still existing.

The first comparison should end at the actual first own-turn6 start snapshot in both arms. Compare every completed native semantic operation/world/control transition from the post-save or post-hydrate anchor through that exact boundary. Native transport IDs may restart and metadata/initialization requests differ by design; those must be separately bound and accounted for, not silently deleted from execution proof. Preserve polling overshoot tails explicitly. Existing CPU predicates are only framework tests; actual v4 source/schema adapter and real raw are still necessary before any recovery certificate.
