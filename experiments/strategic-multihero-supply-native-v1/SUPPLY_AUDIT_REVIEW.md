# Independent first native supply review

The first completed probe is a useful negative result: compatible transfer and query mechanics work, but the intended town cargo was not delivered. `native-review-06/AUDIT.json` records `native_prefix_contract_valid=true`, `generic_transfer_mechanisms_qualified=true`, `cargo_goal_qualified=false`, and `passed=false`. A closed cycle is not a successful logistics job.

The dedicated auditor checks the 362 DirectorSupplyEvent JSON records against supply.jsonl exactly; stable real roles main0/courier2/home3 across ownturn1..6; actual pre-dispatch request payload and allocated ID, registration, server receive and application, callback ACK and both real ACK ledgers; and all seven army slots. It independently checks the eleven compiled source snapshots/build manifest, complete attestation, loaded library identity, native thread-server proof, frozen run inputs and all41 script SHAs. There is no schema4 policy proof or broker data.

Two actual ArrangeStacks transactions establish the failure precisely. Request8, pack183, moves town3 slot0 to courier2 slot1: ten pikemen leave the actual town upper army and enter the courier. Preparation/send/real ACK are client.log8115/8118/8141. Request53, pack183, moves courier2 slot0 to main0 slot1: the original three archers leave the courier and join the main hero. Its lines are10807/10810/10833. Exact donor/recipient seven-slot deltas and unchanged third army conserve all units. The courier retains ten pikemen and no archers; the main remains five pikemen plus three archers. Cargo attribution reports ten picked-up pikemen still undelivered and three noncargo archers transferred. No original reserve creature remains with the courier.

Request54 is the real QueryReply, pack197, query49, reply0. Its callback and payload are bound to the open hero exchange; actual CGarrisonDialogQuery pop is at line10849, followed by query49 destruction, real visitor success and actual ACKs. The subsequent controller query state is closed, intended cycle count increments, and the courier really moves again. Both heroes have real displacement; real scheduling continues on later own turns. These facts certify the generic mechanics only.

There are90 completed scripted transactions, including82 MoveHero transactions. Last request98 is explicitly unfinished and absent from the owned ACK set. The controlled cap6 stop has native exit-15. The report never claims global drain, safe save boundary, whole-game completion, victory, model samples, expert labels, optimizer updates or native recovery. Its last completed-transaction snapshot is distinguished from the final observed, potentially unfinished-tail snapshot.

MoveHero/EndTurn use the existing exact-ID TypedActionApplied visitor-result marker. EndTurn may span the opponent's own EndTurn before its ACK, so unlabelled same-type counts cannot bind those transactions. ArrangeStacks and QueryReply lack that exact-ID server marker; the auditor instead requires exactly one real transport, receive and successful visitor application of their native type inside each uniquely pending callback interval, plus real immutable payload/slot deltas or actual query pop/destruction. Ambiguous intervals fail. ACK success alone is never accepted as a visitor success, because native CGameHandler sends true in its ordinary reply even when a visitor could fail.
